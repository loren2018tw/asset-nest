# ADR-0017：探索時被動 ARP 監聽（網段外觀測）

- 狀態：已接受
- 日期：2026-10-06

## 背景

主動探測只送「已指派／租約／CIDR 內 host」位址，因此同 L2 上不在任何受管網段內的位址（錯設定、私接、其他網段延伸）完全不會被發現。交換器只轉發廣播與「送給本機」的訊框，所以被動觀察只能看到 ARP request（廣播）與自己的回覆；命中率取決於設備是否在監聽窗內主動發 ARP——活躍設備幾乎必露臉，閒置設備可能整天不發。被動監聽需要 raw socket（CAP_NET_RAW），零權限降級模式無法使用。

## 決策

- **只掛在探索掃描**：手動與排程探索時，在被探測網段的介面上被動監聽 ARP；**與主動探測同時進行**（先開 listener、主動批次照跑、最後收割），大網段不增加總時長。快速掃描不做（後續可加）。
- **窗長可調**：`OBSERVATION_PASSIVE_WINDOW_SECS` 預設 60 秒，0＝停用。
- **只記 CIDR 外的 sender**：`0.0.0.0`、multicast／broadcast、本機自身排除；CIDR 內位址由主動探測負責。
- **掛在探測的網段下**：沿用 `ip_presence`＋`observation_event`（ADR-0016），`ip_presence` 加 `out_of_subnet` 旗標（migration 0007），來源 `arp_passive`；同一網段外位址若被兩個 L2 網段看到會各有現況列，MAC 視角查詢自動合併。
- **獨立呈現**：新增「網段外觀測」清單頁（不混入 IP 清單的指派語意）；唯讀、不自動告警或處置（ADR-0014）。
- **降級誠實**：unprivileged／降級模式無被動資料，文件與空狀態明示。

## 理由

- 被動廣播是唯一能看到「不在任何網段內」設備的管道，且不增加探測負擔（listen 不送封包）。
- 重用現況＋事件模型讓 MAC 歷史、保留清理、資產連結一次到位，不需新事件機制。
- 與主動探測併行把窗長成本藏在大網段掃描時間內；小網段才實際等待。

## 後果

- 命中率受設備活動與窗長影響；要提高可調長窗或把監聽擴到快速掃描（後續）。
- 資料以「探測網段」為歸屬；同一 L2 多個受管網段可能出現重複列（各網段視角）。
- `ip_presence` 多一欄；查詢端點須明確只列 `out_of_subnet=1`，IP 清單不受影響。
