# ADR-0016：觀測記錄模型（事件式＋IP 鍵現況）

- 狀態：已接受
- 日期：2026-10-06

## 背景

觀測要同時回答兩個方向的查詢：位址視角（最後可見、被哪些 MAC 輪用）與 MAC 視角（換過哪些 IP、是否常變動）。若每輪掃描全量存樣本，15 分鐘 × 規模 × 一年將成長到千萬列且毫無查詢價值。若以 MAC 當主鍵，無 MAC 的介面（GLOSSARY 允許）無法對應，且 MAC 可隨機化／偽造，不適合作為身份；而管理對象與 Assignment 的鍵都是 `(subnet_id, address)`。

## 決策

- **兩層記錄**：`ip_presence` 現況（主鍵 `(subnet_id, address)`，對齊 `ip_assignments`；記 `last_seen_at`、`last_seen_mac`、`last_seen_source`、`last_checked_at`）＋ `observation_event` append-only 事件（只在變化發生時寫：首見、MAC 變更等；帶來源）。
- **MAC 不是實體也不是主鍵**：以事件屬性保存並建索引；未知 MAC 只記值。兩個方向的查詢由事件與現況推導。
- **列的存在規則**：已指派位址永遠有現況列（才能顯示「從未上線」）；未指派者被看見過才建列。
- **顯示三態**：未觀測、從未上線、N 天前。
- **保留**：事件預設保留 1 年、可設定清理；支援 CSV 匯出。
- 事件種類的完整清單由 spec 定案。

## 理由

- 「變化才寫」讓資料量與掃描頻率脫鉤；`last_checked_at` 區分「離線」與「未涵蓋」，避免盲點被誤讀成離線。
- IP 鍵直接 join 指派（回收判斷的核心查詢），並涵蓋無 MAC 介面；MAC 索引保留反向查詢，不需另立實體。
- 保留期清理只影響歷史深度，不影響現況與宣告。

## 後果

- 需要全量樣本的統計（如「上線率百分比」）不在支援範圍；如未來需要，另案處理。
- 事件保留期縮短會失去久遠的變動史；現況列不受清理影響。
- 新資料表隨下一次 migration 建立（0006）。
