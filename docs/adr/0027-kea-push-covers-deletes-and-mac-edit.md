# ADR-0027：即時推送擴及刪除與 MAC 編輯，匯入以提示替代推送

- 狀態：已接受
- 日期：2026-10-14

## 背景

ADR-0011 明定「介面 MAC 編輯與資產／介面刪除不即時同步，交由完整同步收拾」；ADR-0026 將 `DELETE /assets/{id}` 的 Kea 推送補救列為「另案」；資產 CSV 匯入（ADR-0008）建立保留但不與 Kea 互動、完成訊息也未提示；受管網段的刪除、`kea_subnet_id` 清空／改號與 CIDR 變更（ADR-0023「僅增不刪」）在 Kea 端留下的殘留亦無提示。2026-10-14 的同步完整性檢視（`.scratch/kea-sync-completeness/spec.md`）確認這些缺口會讓 Kea 配發行為與本地宣告不一致，且使用者無從得知。

## 決策

- **刪除家族即時推送**：`DELETE /assets/{id}`、`DELETE /interfaces/{id}` 與草稿取消的「刪除已建立內容」改為「先擷取保留、本地刪除、後逐筆刪除 Kea 保留」；回應由 204 改為 200＋`kea_sync: Vec<KeaSync>`；失敗警示不阻擋本地儲存（沿用 ADR-0011）。
- **介面 MAC 編輯即時推送**：MAC 變更後，對該介面在受管網段的保留指派逐筆 upsert（以新 MAC）；`PATCH /interfaces/{id}` 回應加 `kea_sync`（僅實際推送時出現）。
- **MAC 清空為結構規則**：介面有保留指派時不可清空 MAC（400；與「保留需介面有 MAC」一致，見 ADR-0006）。
- **報廢與資產端指派順序修正**：`POST /assets/{id}/disposal` 改為「擷取保留 → 本地搬移 → 推送刪除」（修正原「先推送後搬移」在搬移失敗時的反向漂移）；`PUT /assets/{id}/assignments` 的推送移至警示偵測之前。
- **匯入不推送、改以提示**：CSV 匯入維持零 Kea 呼叫；回應 `created` 新增 `managed_reservations`（本次建立於受管網段的保留數），前端於其大於 0 時提示執行「Kea 完整同步」。
- **網段層維持只增不刪、加 UI 警示**：不推送 `subnet4-del`；刪除受管網段與編輯受管網段（CIDR 變更、`kea_subnet_id` 清空／改號）時於前端二次確認／警示 Kea 端不會自動清理（殘留需人工處理）；CIDR 不符的完整同步錯誤態維持由報告呈現。
- **失敗原則不變**：失敗僅警示、不阻擋、無重試佇列與同步狀態表；修復仍為完整同步（ADR-0011）。排除範圍仍不推送 Kea（ADR-0020 不變）。

## 理由

- 刪除與 MAC 編輯與「指派、移轉、取消、報廢」同屬會改變 Kea 配發結果的宣告異動；即時推送讓兩側一致，且失敗策略已有既定語意可沿用。報廢（ADR-0026）已建立同類先例，刪除家族不補推送是缺口而非取捨。
- MAC 清空若仍允許保留，會產生「無 MAC 的保留」：完整同步對其跳過、Kea 端永不收斂；以結構規則阻擋與既有「保留需介面有 MAC」一致。
- 匯入維持不推送：批次操作逐筆命令的失敗語意複雜且無計畫可檢視；完整同步已有 dry-run 計畫，提示使用者執行是低風險且可稽核的修復路徑。
- 網段刪除不推送 `subnet4-del`：Kea 端網段可能承載其他工具或人工維護的設定，「刪除只限本系統能表達的形狀」（ADR-0011）在網段層的對偶即「不刪」；以警示代替自動刪除。
- 錯誤路徑修正只是把既有慣例（本地為真實來源、推送在後、失敗警示）貫徹到報廢與資產端指派端點，非新機制。

## 後果

- `DELETE /assets/{id}` 與 `DELETE /interfaces/{id}` 回應由 204 改為 200＋`kea_sync`（前端已相應更新）。
- ADR-0011「介面 MAC 編輯與資產／介面刪除不即時同步」與 ADR-0026「已刪除資產不推送 Kea……另案」由本 ADR 修訂。
- Kea 端殘留（刪除的網段、改號／清空的舊網段與保留）仍不會自動清理；由 UI 警示，人工或未來另案處理。
- `GLOSSARY.md`「推送」定義涵蓋刪除與 MAC 編輯。
