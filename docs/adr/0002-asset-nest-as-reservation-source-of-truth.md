# ADR-0002：保留位址以 asset-nest 為真實來源，單向推送 Kea

- 狀態：已接受
- 日期：2026-10-04

## 背景

Kea 的固定保留可被多處修改（Kea 設定檔、Kealight、未來的 asset-nest）。若不定出唯一真實來源，資料會漂移。

## 決策

- Reservation 的真實來源是 asset-nest；變更以單向推送（upsert／刪除）寫入 Kea。
- Lease 的真實來源是 Kea；asset-nest 唯讀。
- 第二階段加入「讀回對帳」：由 Kea 讀回保留與租約、比對差異並提示，沿用 Kealight 外部變更偵測的精神。
- 明確不做雙向同步。

## 理由

- 雙向同步需要衝突解決語意，成本高且容易產生難以解釋的覆寫行為。
- 「單向推送＋對帳」已涵蓋多數維運情境，且行為可預期。

## 後果

- 若有人直接在 Kea 端修改保留，該變更不會被吸收，將在對帳時被標示為漂移。
- 推送介面需具備冪等性與可重試性（功能階段落實）。
