# ADR-0008：CSV 資產匯入——格式與寫入語意

- 狀態：已接受
- 日期：2026-10-04

## 背景

功能階段一（見 `.scratch/asset-ip-management/spec.md`）將「匯入（Excel/CSV）」列為後續階段。實務上初次導入與新進設備建檔都是一次數十至數千台，逐筆開啟對話框不可行；且舊清冊通常以 Excel 維護，欄位與系統不同。

設計目標有二：(1) 提供固定的匯入格式，讓維運者可先把資料整理成系統可讀的 CSV；(2) 一次匯入即建立資產、其網路介面與 IP 指派三者，避免匯入後還要逐台補 MAC／IP。

格式與語意經三輪逐題確認後凍結。**本 ADR 的欄位總表是整理匯入檔案的權威依據**；可直接使用的範本檔為 `docs/資產匯入範本.csv`（UTF-8 BOM）。

## 決策

### 檔案格式

- 第一列必為標題；標題 trim 後比對，英文不分大小寫（`mac`／`MAC` 皆可）；欄位順序不拘。
- 重複標題＝錯誤；未知標題＝忽略並在預覽提示；缺「描述」或「位置」標題＝錯誤。
- 編碼：UTF-8（可含 BOM）；非 UTF-8 時以 Big5（CP950）解讀，並在預覽顯示實際使用的編碼供核對。
- 半形逗號分隔；引號規則依 RFC 4180（欄位內可含逗號、換行，雙引號以 `""` 轉義）；換列 LF／CRLF 皆可；空行忽略。
- 只處理 CSV；`.xlsx` 二進位格式不在範圍內。
- 單位格文字一律 trim；空白視為未填。

### 欄位總表（14 欄）

| # | CSV 標題 | 必填 | 格式與規則 |
|---|---------|------|-----------|
| 1 | 財產編號 | 否 | 與既有資產或檔內重複 → 警示列（不擋） |
| 2 | 描述 | **是** | 空白 → 錯誤列 |
| 3 | 位置 | **是** | 空白 → 錯誤列 |
| 4 | 設備序號 | 否 | 重複（檔內或既有）→ 警示列 |
| 5 | 廠牌 | 否 | |
| 6 | 型號 | 否 | |
| 7 | 購置日期 | 否 | `YYYY-MM-DD`／`YYYY/M/D`／`YYYY.M.D` 皆可，正規化為 `YYYY-MM-DD`；無法解析 → 錯誤列 |
| 8 | 年限 | 否 | 非負整數（年） |
| 9 | 備註 | 否 | |
| 10 | 標籤 | 否 | 以直線符號 `\|` 分隔；trim、略過空值、不分大小寫去重 |
| 11 | MAC | 否 | 冒號／連字號／點號／無分隔皆可 → 正規化為小寫冒號；格式錯 → 錯誤列；重複（檔內或既有）→ 警示列 |
| 12 | IPv4 | 否 | 須為合法 IPv4 host、屬既有 v4 網段、非 network／broadcast（`/31`、`/32` 全數為 host）、非 pool 內、未被指派、檔內不重複，否則錯誤列。**有 MAC → 一律建保留（reservation）；無 MAC → 手動（static）** |
| 13 | IPv6 | 否 | 合法 IPv6、屬既有 v6 網段（登錄制，含 network 位址）、未被登錄、檔內不重複，否則錯誤列；用途恆為手動 |
| 14 | hostname | 否 | 僅「有 MAC＋IPv4」（保留）的列可填；其餘情況有值 → 錯誤列 |

### 寫入語意

- **只新增**：每一列建立一筆新資產；不做更新、不做比對合併。
- 「MAC／IPv4／IPv6／hostname」任一有值 → 建立一個預設介面 `eth0`；全空 → 只建資產，不建介面。
- IPv4 用途：有 MAC → 保留（Kea 固定配發）；無 MAC → 手動。主機自行手動設定 IP 時，DHCP 端存在保留不影響運作，故保留為安全預設。
- IPv6 恆為手動（static）；v6 無保留概念。
- hostname 僅在保留情況可填（等同現行「僅保留用途可填 hostname」規則）。
- 網段（CIDR）必須**事先建立**；IP 不屬於任何既有網段即為錯誤列。
- **全有全無**：任一列有結構錯誤 → 整批不匯入（不寫入任何資料）。
- 語意警示（重複財產編號／設備序號／MAC）僅提示、不阻擋（兩層原則見 ADR-0006）。
- 預覽與結果提供「問題列報告」下載：原列號＋14 欄原始值＋原因，供回 Excel 修正後重新上傳。

## 理由

- 中文標題：檔案由人以 Excel 整理，中文欄名最直覺；未知欄位忽略讓清冊可保留輔助欄。
- 標籤以 `|` 分隔：不必處理引號規則、不易與內文標點混淆。
- 日期容忍 `YYYY/M/D` 等變體：Excel 匯出常見格式，容忍可少一輪重工。
- MAC 格式容忍：沿用系統既有正規化，減少人工轉換。
- Big5 自動偵測：台灣辦公室的 Excel「另存 CSV」常為 Big5，避免打開變亂碼的來回。
- IPv4 一律保留（無 MAC 除外）：本系統價值在 Kea 保留；保留與主機手動設定並存仍可運作，批量誤設定的成本高於逐筆補設。
- 全有全無：匯入是批次動作，半套資料的清理成本高於整批修正後重來。

## 後果

- 欄位名稱、分隔字元、日期容忍度與用途推導自此視為對外契約；破壞性改動需新 ADR 或格式版本化（新增選填欄位視為相容）。
- 匯入不含「一台資產多介面」；有此需求須另開格式或流程（例如多列式或第二階段）。
- 修正錯誤一律以「下載問題列報告 → 回 Excel 修正 → 重新上傳整檔」為流程；不做線上編輯。
