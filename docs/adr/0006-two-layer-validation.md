# ADR-0006：驗證分兩層——結構錯誤阻擋、語意衝突標記

- 狀態：已接受
- 日期：2026-10-04

## 背景

Kealight 的四個衝突規則（DuplicateHwAddress、IpInUse、IpInPool、IpOutOfSubnet）描述的是「可疑但不必然錯誤」的狀態：例如 Kea 官方允許保留位址落在動態池內，硬擋會與實際可運作的設定牴觸，也讓維運被迫繞路。另一方面，有些規則是系統結構的必要條件（網段不得重疊、同一網段位址不得重複指派、Reservation 需要 MAC），這類錯誤若放行，資料模型本身即失去意義。

## 決策

驗證一律歸入兩層之一：

- **結構規則：阻擋儲存。** 網段重疊、CIDR／pool／gateway 合法性、MAC 空白的介面不可設 Reservation、同一 Subnet 同一 IpAddress 不得重複指派、非空網段不可刪除。
- **語意衝突：標記提示、不阻擋。** IpInPool、IpOutOfSubnet、DuplicateHwAddress；以列徽章、儲存警示、網段計數呈現。IpInUse 已由「同網段不重複指派」的結構規則涵蓋，詞彙保留供對帳階段與 Kea 比對。

## 理由

- 衝突是給人判斷的資訊，不是閘門：Kea 允許的組態不該被 UI 拒絕。
- 結構條件若放行將破壞不變條件，必須擋在資料邊界。

## 後果

- 未來新增任何檢查時，必須先歸類為結構或語意，不得混用。
- 語意衝突的呈現方式需保持一致（徽章／警示／計數）。
