# ADR-0018：觀測執行外移至觀測代理（後端只留租約與接收）

- 狀態：已接受
- 日期：2026-10-06

## 背景

v1 的 IP 觀測由 asset-nest 本機執行：只涵蓋與伺服器同 L2 的網段（ADR-0015）、主動探測需要特權（`CAP_NET_RAW`），且「哪個網段要觀測」以網段層開關（`observed`、探索開關與間隔）表達。跨路由網段在遠端 agent 出現前一律「未觀測」。

把探測綁在伺服器上帶來持續成本：伺服器必須位在目標 L2、必須持特權發送探測、每個網段的觀測設定與覆蓋語意和伺服器本機位置（`is_local`）糾纏。相對地，觀測點本質上應存在於目標網段裡；伺服器的核心職責是資料（宣告、租約、彙整與呈現）。

## 決策

- **觀測執行全面外移**：主動週期掃描與持續被動監聽一律由**觀測代理**執行，每個要觀測的網段安裝一個代理。代理送出原始觀測（掃描的 checked／seen 結果、被動 sender），由後端做 CIDR 內外分類與事件推導（ADR-0016 模型不變）。
- **後端保留**：Kea 租約觀測（來源 `kea_lease`）、觀測入庫與讀取、現況／事件／衝突／歷史／網段外觀測呈現、事件保留清理。
- **後端移除**：本機探測（`probe`）、掃描服務與排程器、網段觀測設定（`observed`、探索開關、探索間隔、上次探索）、`POST /subnets/{id}/sweeps` 與「立即掃描」介面、探測相關環境變數、systemd 的 `CAP_NET_RAW`。
- **覆蓋語意改由代理健康決定**：網段有近期回報的代理＝已涵蓋；代理失聯＝該網段回到「未觀測」語意，既有資料標示過期而非刪除。`last_seen_source` 續用 `arp`／`arp_passive`／`kea_lease`（記手段，不記執行者）。
- 伺服器所在網段若要觀測，同樣以代理涵蓋（可與伺服器同機、獨立安裝）。

## 理由

- 觀測點必須在目標 L2；「一個網段一個代理」讓覆蓋與代理一一對應，網段層設定歸零、覆蓋語意不再需要使用者維護。
- 後端卸下特權與網路位置限制；資料路徑單一（代理推送→後端接收），測試與維運單純。
- 持續被動監聽取代「探索掃描才開窗」的機制（ADR-0017）：命中率不再受窗長限制，發現能力只增不減。
- 既有記錄模型與呈現不動，改動集中於來源端，migration 與前端調整最小。

## 後果

- 部分取代 ADR-0015（本機探測、同 L2 範圍限制、兩層掃描節奏）與 ADR-0017（探索時被動窗機制）；觀測與宣告分離（ADR-0014）與記錄模型（ADR-0016）沿用。
- 未安裝代理的網段永遠「未觀測」；這是刻意的覆蓋邊界，不是缺陷。
- 觀測代理成為系統中唯一對網路發送探測的元件；掃描頻率與限速屬代理設定。
- 伺服器升級後觀測能力歸零，直到至少一個代理安裝完成；安裝摘要與文件需明示。
