# ADR-0007：資產端指派入口與確認後原子移轉

- 狀態：已接受
- 日期：2026-10-04

## 背景

功能階段一原先只在 IP 管理頁提供指派入口（見 spec §4.3）。實際維運時，工程師常從「某台設備要給哪個 IP」的角度出發：在資產清單或資產編輯對話框看到介面，就希望直接指派位址，不必先切到 IP 管理頁、找到網段、再搜尋資產。

另一個情境是換介面：位址已指派給 A 介面的網卡，現在要改派給同一資產的 B 介面（例如網卡更換）。若照既有網段端點一律阻擋（「位址已被指派給其他介面，請先取消指派」），使用者必須先取消、再重新指派；兩步之間若中斷，位址會暫時消失、也容易忘記收尾。但直接允許覆蓋又會讓「未經確認就搶走他人位址」成為預設行為。

## 決策

- 資產管理列表每列與資產編輯對話框的已儲存介面列提供「指派 IP」入口；指派對象仍是 Interface（見 ADR-0005）。
- 輸入 IP 後由後端反推所屬網段（網段不重疊，至多一個；找不到即回 400「位址不在任何網段內」）。
- 位址已指派給其他介面時，`transfer: false` 先回 400 `address_assigned_elsewhere`，附目前指派對象（資產描述／位置、介面名稱／MAC、網段）；UI 顯示確認對話框，確認後以 `transfer: true` 重試。
- 移轉以單一交易原子實作：同一交易內刪除舊指派＋建立新指派（取消＋重新指派），不留歷程；v4／v6 皆適用。
- 移轉不重驗出界／落池：語意衝突標記不阻擋（見 ADR-0006），沿用既有 `assign()` 對「既有位址」的處理原則；結構規則不因移轉而放寬（保留需 MAC、同一介面同一網段至多一位址、v6 用途固定 static）。
- 位址已指派給同一介面時為更新用途／hostname，`transferred: false`。
- 既有 `PUT /subnets/{id}/ips/{address}/assignment` 行為不變：已指派給其他介面仍直接阻擋。

## 理由

- 從資產視角指派符合實際工作流；入口與指派對象（介面）一致，不改變資料模型。
- 「先提示、經確認才移轉」把覆蓋他人指派的決定留在人身上；後端仍保有結構防線。
- 原子交易避免「取消成功、建立失敗」造成位址遺失或半套狀態；不留歷程與 ADR-0005 一致（換介面即取消後重新指派）。
- 網段端點維持原本阻擋語意，讓 IP 管理頁的既有操作與測試不受影響；兩端語意差異由本 ADR 記錄。

## 後果

- 換介面的操作在資產端是一步（確認後移轉）、在 IP 管理頁仍是兩步（先取消再指派）；未來若要統一，需另案評估。
- 移轉會改變指派列 id（刪除＋新增），不可依賴 id 追蹤同一指派；若未來需要稽核，須另立歷程機制。
- 位址若因網段縮小而「出界」，將不屬於任何網段，資產端無法以此路徑移轉（回 `no_subnet`）；此為已知邊界。
