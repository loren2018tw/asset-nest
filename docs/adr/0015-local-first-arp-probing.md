# ADR-0015：本地優先的探測策略（ARP 為主、最小權限）

- 狀態：已接受
- 日期：2026-10-06

## 背景

要回答「某位址最近是否可見」，探測手段各有盲點：ICMP 被 Windows 預設防火牆擋下、被動讀 ARP／neigh 表只涵蓋近期有互動的主機、TCP 探測只命中少數開埠服務。網路規模可能是 /16，整段 ICMP 掃描又貴又沒必要。服務以非特權使用者執行（deploy 的 systemd 硬化）。跨 VLAN 需要遠端探測點，但 v1 先把範圍收斂。

## 決策

- **v1 只觀測與本機同 L2 的網段**（本機介面位址落在該 Subnet 內者）；跨路由網段暫不觀測，未來以遠端 agent 補足。
- **主動探測以 ARP 為主**：同 L2 的存活主機通常必須回應 ARP（不受主機防火牆阻擋），解 ICMP 盲點；ICMP 僅為選配補充，非主要判定。
- **Kea 租約為被動輔助來源**：`cltt`／`state` 提供 DHCP 裝置的活動訊號，涵蓋不回應任何探測的裝置。
- **兩層節奏**：快速掃描（已指派＋有租約位址）每 15 分；探索掃描（整段）預設每日離峰、限速、可調；兩層皆可手動觸發。
- **最小權限**：systemd 單元加 `CAP_NET_RAW`（不給 root）；零權限替代方案（UDP 觸發 kernel ARP 解析後讀取 neigh）保留為降級模式。
- **來源可插拔**：觀測寫入走單一來源介面，資料記錄來源；未來 agent 以同一格式推送。

## 理由

- ARP 是「同一廣播域內誰活著」最直接、最便宜的證據；只掃有意義的集合（指派＋租約）讓大網段的負擔與網段大小脫鉤，探索掃描才需要整段。
- 少數 CAP 換到直接探測能力，比把整個服務提升為 root 或依賴間接的零權限技巧穩妥。
- 先做本地、把 agent 的介面預留好，避免未來重構資料路徑。

## 後果

- deploy 安裝與既有升級需更新 systemd 單元（`AmbientCapabilities=CAP_NET_RAW`）。
- 跨 VLAN 網段在 agent 出現前一律顯示「未觀測」；這是刻意的覆蓋邊界，不是缺陷。
- `--no-kea` 指向遠端 Kea 時，租約仍經控制通道取得；ARP 探測範圍仍限本機所在 L2。
