# ADR-0009：網段 CSV 匯出匯入——格式與只新增語意

- 狀態：已接受
- 日期：2026-10-04

## 背景

資料庫重建需求：空庫（或刪除 `asset-nest.db`）後要快速還原網段設定，因為資產匯入（ADR-0008）要求網段必須先存在，流程是「匯出備份 → 刪庫 → 先匯入網段 → 再匯入資產」。此前網段只能逐筆在 UI 建立。

## 決策

- 格式：CSV，欄位＝名稱／CIDR／Gateway／Kea subnet-id／位址池／備註；僅 CIDR 必填。標題列、編碼（UTF-8／Big5）、大小與列數上限、引號規則沿用 ADR-0008。
- 位址池以 `|` 分隔多段、每段 `起點-終點`（沿用標籤分隔符的取捨：不需處理引號、不易與內文標點混淆）；僅 IPv4 可有；v6 留空，有值為錯誤列。
- **只新增**：CIDR 已存在（檔內或既有）或與既有／檔內網段重疊 → 錯誤列；任一列結構錯誤整批不寫入；不做 upsert、不刪除。
- dry-run 預覽與問題列報告比照資產匯入；正式匯入單一交易。
- 匯出為全部網段（v4 先、v6 後，同族依 CIDR 數值）、UTF-8 BOM。

## 理由

- 用途是空庫重建而非批次編輯：只新增與資產匯入一致，並避免「一份編輯過的檔案覆寫線上網段」的風險（upsert 可能改動 gateway、Kea subnet-id、pool，引發大範圍語意衝突）。
- CIDR 雖可作穩定鍵，但現階段沒有以檔案更新既有網段的需求；重建流程（先網段、後資產）即可滿足。
- 修改既有網段仍走 UI 編輯對話框（有即時結構檢查），維持單筆操作的可控性。

## 後果

- 以匯入更新既有網段（upsert）或刪除不在檔內的網段不在支援範圍；未來若有需求須新 ADR 或格式版本化。
- 欄位名稱與 pool 表示法自此為對外契約；新增選填欄位視為相容。
