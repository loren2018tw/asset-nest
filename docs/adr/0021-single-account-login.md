# ADR-0021：單一帳號登入與簽章工作階段

- 狀態：已接受
- 日期：2026-10-07

## 背景

系統目前沒有登入驗證（`auth.rs` 是 no-op 插槽；ADR-0019 亦載明介面登入認證另行處理）。asset-nest 是單一管理者的內部 IT 工具，沒有多使用者與角色的需求；但要避免未授權的人瀏覽與操作（資產、IP、Kea 同步）。Kealight 已有「簡易密碼」先例（其 ADR-0005：共用密碼、cookie 登入頁），本系統沿用其精神但明確化為「單一帳號＋密碼」。

候選：(A) 環境設定單一帳號＋簽章 cookie；(B) 資料庫使用者表＋密碼雜湊；(C) 反向代理層 Basic 認證。B 對單人工具過重（建帳號、改密碼、忘記密碼流程都得自建）；C 使應用層無法在 UI 呈現登入／登出／過期，也讓「登入界面」落在 nginx 設定而非產品。

## 決策

- **帳密來源**：環境設定 `AUTH_USERNAME`／`AUTH_PASSWORD`；未設定或空白逐欄位套用預設 `admin`／`admin`；啟動時使用預設值即記警告。**不提供停用登入的設定；密碼明文存放**（env 檔權限 0640、root 可讀，與 Kea／代理認證碼同形式），比對採常數時間。
- **工作階段**：無狀態簽章 cookie（`asset_nest_session`；HMAC-SHA256，金鑰由帳密推導）。固定 30 天、不續期；登出＝清除 cookie；帳密變更使所有裝置立即失效。不引入資料庫 session 表。
- **邊界**：`/api` 子樹為認證邊界；免登入白名單＝`GET /api/health`（安裝與 CI 健康檢查）、`POST /api/v1/agents/heartbeat`、`POST /api/v1/agents/observations`（代理有自身認證碼，見 ADR-0019）、`POST /api/v1/login`、`POST /api/v1/logout`。其餘未登入一律 401 JSON。前端靜態檔公開；UI 以路由守衛導向登入頁。
- **cookie 屬性**：HttpOnly＋SameSite=Lax＋Path=/；不設 Secure——傳輸安全由部署解決（nginx 前門見 ADR-0022；HTTPS 日後由 certbot 加上）。
- **v1 非目標**：rate limit、多帳號／角色、密碼變更 UI、工作階段天數可調、跨來源部署。

## 理由

- 單人工具的最小充分防護；無建表、無密碼重設流程、零維運。Kealight 已驗證此形態可落地。
- 金鑰由帳密推導讓「改密碼＝全體登出」免費成立；無狀態使重啟不掉線。
- 以白名單思維界定公開端點（而非黑名單），新增端點預設受保護；代理與健康檢查不受影響。
- 明文密碼與「不設 Secure」是同一個現實：本系統不含 TLS，卻不能因此讓外部任意進門。部署邊界（loopback＋nginx）承擔傳輸安全，應用層承擔存取控制（見 ADR-0022）。

## 後果

- 使用者須每月重新登入；過期以 401 通知呈現。
- 帳密在 env 檔明文；任何能讀檔或取得 cookie 的人可冒用至到期（HTTP 下 cookie 可被同網段竊聽——TLS 完成前的已知風險，文件明示）。
- 無逐裝置撤銷；改帳密是唯一全域撤銷手段。
- `AppState` 的認證為選配欄位（測試路徑不附掛）；正式入口 `main.rs` 一律附掛——不提供任何環境變數關閉。
