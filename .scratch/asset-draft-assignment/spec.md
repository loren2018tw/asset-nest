# 規格：新增資產的介面預填與指派草稿

- 狀態：已定案（2026-10-11，兩輪逐題確認）；已實作（2026-10-11，見票 01–06）。
- 詞彙依 `GLOSSARY.md`；關鍵取捨見 `docs/adr/0025`。
- 沿用：`docs/adr/0005`（指派以 Interface 為對象）、`docs/adr/0006`（兩層驗證）、`docs/adr/0007`（確認後原子移轉）、`docs/adr/0011`（Kea 推送）、`.scratch/asset-ip-management/spec.md` §4.1／§5。

## 1. 範圍

### 1.1 本階段包含

- 新增資產對話框在資產尚未儲存時即可指派 IP（**指派草稿**）；取消新增＝介面與指派都不落地。
- 按「新增介面」時若介面清單為空，名稱預填 `eth0`（新增與編輯模式一致）。
- 編輯模式中「尚未儲存的介面草稿」同樣適用指派草稿。

### 1.2 本階段不含

- 後端 API 變更（指派落地沿用 `PUT /assets/{id}/assignments`）。
- 編輯既有資產中「已儲存介面」的指派行為變更（維持立即落地、立即推送 Kea）。
- Kea 租約入口的指派預填（租約位址多為池內，不可指派）。
- 指派歷程。

## 2. 名詞

- **指派草稿（assignment draft）**：存在對話框記憶體、尚未落地的指派；綁定一筆介面草稿（或編輯模式中新增的介面草稿）。落地前不呼叫指派 API、不推送 Kea。
- **落地（land）**：指派草稿於儲存時經 `PUT /assets/{id}/assignments` 建立為正式指派。
- **介面草稿**：既有概念（`id === null`＝尚未儲存的新介面）。

## 3. 介面預填 eth0

- 按「新增介面」時，若**當下**介面清單為空（新增或編輯模式皆同），新列名稱預填 `eth0`；MAC、備註空白。
- 開啟對話框時**不**自動建立介面列（不是所有資產都有網路介面）。
- 由 Kea 租約進入時已有預填介面（`eth0`＋租約 MAC），清單非空故不受影響；刪除後再新增仍依「清單為空」規則預填。

## 4. 指派草稿

### 4.1 入口與適用對象

- 介面列「指派 IP」按鈕一律顯示：
  - **已儲存介面**（`row.id !== null`）→ 現行立即指派流程（不變）。
  - **介面草稿**（`row.id === null`）→ 指派草稿（新增）。
- 指派對象固定為該列介面（同現行 `fixedInterface`）。

### 4.2 指派對話框（草稿模式）

外觀與現行指派對話框一致；差異如下：

- 副標顯示目前表單的「財產編號(描述)（位置）（未儲存）」；表單尚未填描述時顯示「新資產」、未填位置時顯示「未填位置」。
- 介面欄唯讀顯示該草稿列的名稱／MAC。
- 不顯示對話框自身的「已指派 IP」清單。
- 不呼叫資產／指派 API；位址候選查詢照舊（唯讀）。
- 送出＝建立或更新草稿後關閉對話框（不落地、不推送 Kea）。

### 4.3 草稿建立時的把關

- 格式：同現行（`parseAddress`）；保留（reservation）於草稿列無 MAC 時停用（同現行）。
- **v4**：以候選查詢的 `query_status` 擋下 `in_pool`／`excluded`／`out_of_subnet`（訊息同現行提示文字）；`static`／`reservation`（已指派他處）允許，提示「送出後可確認移轉」，於儲存時確認。送出時若尚無該位址的查詢結果則即時補查；查詢失敗則擋下（「無法查詢位址狀態」）。
- **v6**：以全部網段清單（`GET /subnets`）比對 CIDR；不在任何網段 → 擋下（「位址 X 不在任何網段內」）；網段清單未載入時不做此預檢（後端把關）。
- **同介面同網段至多一筆**：比對該介面（草稿列）的既有指派與草稿；同位址（解析後數值相等，v6 不同寫法視為相同）＝更新該草稿（用途／hostname）；不同位址＝擋下（「此介面在此網段已有位址 X（同一介面同一網段至多一個位址）」）。
- 後端仍為最終權威。

### 4.4 顯示（資產對話框底部「已指派 IP」）

- 顯示條件：編輯模式一律顯示；新增模式於有草稿或已落地指派時顯示。
- **草稿列**：位址、網段（已知時：v4 由 `query_status`、v6 由網段清單）、用途、hostname、「（未儲存）」；操作只有「取消指派」（移除草稿、不跳確認）。
- **已落地列**：同現行（「IP 管理」連結、「取消指派」跳確認、立即生效）。
- 草稿列**不提供**「IP 管理」連結（指派尚未存在）。

### 4.5 連動

- 刪除介面草稿列：連動移除其指派草稿；確認文字加上「將一併取消 N 筆尚未儲存的指派」。
- 編輯介面草稿的名稱／MAC：草稿指派跟隨；保留需 MAC 於儲存前預檢（見 §5.1）。

## 5. 儲存

### 5.1 順序

1. 預檢：每筆草稿若 `purpose = reservation` 且其介面草稿無有效 MAC → 阻擋，**不建立任何資料**。
2. `createAsset`／`updateAsset`（既有）。
3. `emit saved`（既有）。
4. `syncInterfaces`（既有）。
5. 逐筆落地指派草稿：`PUT /assets/{id}/assignments`；同位址＝更新、已指派他處＝確認後 `transfer: true`（現行文案與流程）。
6. 全部落地 → 關閉對話框；warnings／Kea 推送提示照舊。

### 5.2 失敗（遇錯即停）

- 任一筆失敗（含移轉確認被取消）→ 停止後續；已成功者自草稿移除、重新載入後以「已指派」呈現；失敗者保留草稿；對話框保持開啟、顯示錯誤；再按「儲存」重試（資產已建立不重建、已落地跳過）。
- 移轉被取消的訊息：「位址 X 未移轉，指派尚未建立。」

### 5.3 取消

- 未曾建立資產：直接關閉，草稿全丟棄（不跳確認）。
- 已建立資產且尚未完成儲存（`savedAssetId !== null`）：跳三選項對話框——
  - **繼續編輯**：關閉確認框、留在表單。
  - **保留已建立內容**：關閉對話框，已建立的資產／介面／指派保留。
  - **刪除已建立內容**：`DELETE` 該資產（連動刪除介面與已落地指派）後關閉；失敗則回到表單顯示錯誤。
- 對話框關閉後通知外層刷新清單。

## 6. 邊界

- 部分失敗後再儲存成功：只剩未落地草稿重試；`savedAssetId` 避免重複建立。
- 同一介面 v4＋v6 各一筆草稿：允許（跨網段各一）。
- 位址於草稿期間被他人取得：儲存時由後端擋、走移轉確認。
- 編輯模式新增的介面草稿亦適用草稿指派，儲存時一併落地；編輯模式的已儲存介面不受影響。
- 草稿列被刪除後，其指派草稿即不存在（無需另行清理）。
