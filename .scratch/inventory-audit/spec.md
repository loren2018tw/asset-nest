# 規格：清冊稽核

- 狀態：已定案（2026-10-09，三輪逐題確認），待實作。
- 詞彙依 `GLOSSARY.md`（清冊、清冊稽核、財產編號）；檔案直讀與比對語意的權威文件為 `docs/adr/0024`；檔級錯誤的兩層精神沿用 `docs/adr/0006`。

## 1. 範圍

### 1.1 本階段包含

- 側欄「資產管理」新增「清冊稽核」頁；一次上傳 1～10 個財管盤點清冊（`.xls`／`.xlsx`），後端以記憶體解析、不落地。
- 以財產編號比對清冊與系統資產，列出「清冊有、系統沒有」與「系統有、清冊沒有」兩張結果表；各表可關鍵字篩選、下載 CSV（UTF-8 BOM）。
- 逐檔摘要（檔名、種類、資料列數、略過數）與整體摘要（清冊筆數、系統筆數、相符、兩向差異）。
- 檔級錯誤整批拒絕、逐檔回報。

### 1.2 本階段不含

- 相符清單的檢視（僅數字）。
- 任何寫入動作（補登、報廢、標記）；稽核結果與歷史不保存（重新上傳即重算）。
- CSV 上傳；`.xls` 解析不延伸用於既有資產匯入（該路徑依 ADR-0008 仍為 CSV）。
- 保管人、財產／物品類別等資料模型擴充（種類僅為來源標示）。

## 2. 檔案解析規則

- 接受 `.xls`（BIFF）與 `.xlsx`（OOXML）；其他格式＝檔級錯誤。解析以位元組進行，不落地檔案。
- 每個工作表都掃描：表頭列＝前 10 列內含有「財產編號」儲存格的那一列；表頭所在工作表為資料表。找不到表頭的工作表略過（財管的空白三聯頁即 0 列）。
- 表頭比對＝去除所有空白後字串相等（例：`形式\n品名` ≡ `形式 品名` ≡ `形式品名`）；欄位依表頭文字定位、不倚賴欄序、未知欄忽略；重複表頭取第一個。
- 取用欄位：財產編號（必備）、財產名稱、形式品名、存放地點、保管人員、備註；缺欄＝該欄輸出空。
- 資料列：表頭以下、編號欄含數字者；列號＝該工作表實際列號（1-based）。
- 略過列：編號欄不含數字、但財產名稱欄有值者 → 不參與比對、計入該檔略過數（今天 0）；其餘（全空列、頁尾文字如「保管人…」「說明：」「本單…」「第 一 聯」）忽略。
- 種類判定：表頭上方文字（同工作表）含「物品」→ 物品，否則財產；實務上一檔＝一張資料表，多張時以第一張的判定為該檔種類；僅作來源標示。
- 儲存格一律視為文字（不轉數字或日期）。

## 3. 比對規則

- 比對鍵正規化：去除前後空白；中間所有空白（換行、連續空白、全形空白 U+3000）壓縮為單一半形空格；ASCII 英文字母轉小寫。除此之外不做任何轉換。
- 系統側範圍＝「財產編號非空白」的全部資產；清冊側＝全部檔案的全部資料列（合併為一集合）。
- 相符＝比對鍵同時存在兩側；`matched`＝兩側皆有之鍵數（去重）。
- 「清冊有、系統沒有」＝清冊列的鍵不在系統鍵集合；「系統有、清冊沒有」＝系統資產的鍵不在清冊鍵集合。輸出保留原文（不清洗、不折疊）。
- **無慣例特例**：「(併主機)」尾註、「x」前綴、「無帳」等自訂編號照字面參與比對（見 ADR-0024）。
- 重複：同鍵多列（同檔、跨檔、系統內）逐列呈現、標示「同鍵重複」；相符統計仍以鍵計。
- 排序：兩張差異表皆依比對鍵升冪（穩定排序）。

## 4. 檔案級錯誤（整批拒絕，400）

任一情況即整次稽核不執行：

- 檔案非 `.xls`／`.xlsx` 或無法解析。
- 找不到任何「財產編號」表頭，或整檔（全部工作表加總）無資料列。
- 單檔 > 5 MB、單檔資料列 > 5,000、檔案數 > 10。

回應：`{ "error": "validation_error", "message": "…", "details": { "field": "file", "files": [{ "filename": "…", "message": "…" }] } }`；`message` 為中文摘要（多檔以「；」串接），`files` 逐檔列原因（沿用 `ApiError` 格式，見 `backend/src/api/error.rs`）。

## 5. API

### 5.1 端點

`POST /api/v1/inventory-audit`；`multipart/form-data`；檔案欄位名 `file`，可重複 1～10 次。純唯讀（不得寫入任何資料表、不得落地檔案）。

### 5.2 回應（200；以下數值為 2026-10-09 實測示意）

```json
{
  "files": [
    { "filename": "資訊組財產清冊.xls", "kind": "property", "total": 597, "skipped": 0 }
  ],
  "summary": {
    "list_total": 769, "list_property": 597, "list_item": 172,
    "system_total": 874, "matched": 764,
    "missing_in_system": 5, "missing_in_list": 110
  },
  "missing_in_system": [
    { "file": "資訊組財產清冊.xls", "kind": "property", "row_number": 326,
      "property_no": "3140101-03\n\n3001388", "name": "…", "form": "…",
      "location": "…", "custodian": "…", "note": null, "duplicate": false }
  ],
  "missing_in_list": [
    { "asset_id": 877, "property_no": "3000874", "description": "電腦機房(機櫃)",
      "location": "電腦機房(機櫃)", "note": "166823", "duplicate": false }
  ]
}
```

- `kind`：`property`（財產）／`item`（物品）。
- `total`＝資料列數；`skipped`＝略過列數。
- `duplicate`＝同鍵在該側出現多列。
- 無差異時陣列為空；HTTP 仍為 200。

## 6. 操作界面

- 路由 `/inventory-audit`；側欄「資產管理」區塊新增「清冊稽核」（icon `fact_check`；active＝路徑前綴）。
- `InventoryAuditPage.vue`：
  1. **上傳**：`QUploader`（`multiple`、`accept=".xls,.xlsx"`、關閉自動上傳、`hide-upload-btn`）；說明（1～10 檔、每檔 5 MB／5,000 列、整批全有全無、唯讀）；已選檔案清單（檔名、大小、可移除）；「開始稽核」（無檔停用）。
  2. **結果**：整體摘要 chips（清冊合計（財產 X＋物品 Y）／系統資產／相符／系統缺少／清冊缺少）；逐檔摘要列（檔名、種類 badge、資料列數、略過數）；兩張結果表：
     - 「清冊有、系統沒有」欄位：來源（財產／物品）、檔案、列號、財產編號（原文）、財產名稱、形式品名、存放地點、保管人員、備註、同鍵重複標示；工具列：關鍵字篩選、筆數、下載 CSV。
     - 「系統有、清冊沒有」欄位：財產編號（原文）、描述、位置、備註、同鍵重複標示、操作（「在資產清單檢視」→ `/assets?q=<編號原文>`）；工具列同上。
     - 表格用 q-table 虛擬滾動、固定高度；篩選為前端子字串比對。
     - 「重新上傳」清除結果、回到上傳步驟。
  3. **錯誤**：檔級錯誤 → 頁面錯誤區塊（逐檔檔名＋原因）＋`$q.notify`（negative）；不產生結果。
- CSV 匯出（前端產生）：UTF-8 BOM、CRLF、RFC 4180；檔名 `清冊稽核_系統缺少_YYYYMMDD.csv`／`清冊稽核_清冊缺少_YYYYMMDD.csv`；欄位同表格（「操作」欄不入 CSV；「同鍵重複」以「是」／空 表示）。
- `AssetsPage` 支援 `route.query.q` 初始化搜尋字串（供上述連結）。

## 7. 實作預設（可改）

- 上限：每檔 5 MB／5,000 資料列、單次 10 檔（沿用 ADR-0008 慣例）。
- 後端新增 `calamine` 依賴；`backend/src/inventory_audit.rs`（解析＋比對）與 `backend/src/api/inventory_audit.rs`（HTTP）。
- 比對於記憶體完成；系統側以單一查詢取得編號非空白資產。
- 兩張差異表在後端即排序；前端不再重排。
